# Python 商品复制

## 桌面通用入口

双击桌面的 `淘宝商品复制与上架.bat`，或项目根目录的 `启动商品复制工具.bat`。

Chrome 启动时最大化，类目页、发布页和图片选择器均使用实际窗口大小，不再强制设为 1600×1400。更新后需结束旧任务并重新打开浏览器，已打开的旧任务不会自动加载新代码。

主图使用逐张上传：每次只传一个文件，等待上传成功和主图回读后，至少间隔3秒再处理下一张。检测到安全验证或操作频繁提示时暂停，由用户在浏览器完成验证或等待提示消失，再在日志窗口按回车继续。提示仍存在或上传超时会停止，不会自动重传。此节奏调整不保证平台不再要求验证。

点击“本地上传”前先监听文件选择事件，再通过该事件设置本次文件，避免 Windows“打开文件”对话框残留。更新前已经弹出的系统窗口需先手动取消，新任务才会使用新的事件处理流程。

表单修改后自动保存到 `output/desktop-last-form.json`，启动任务和关闭窗口前也会保存。再次打开时恢复全部输入，包括商品链接、属性 JSON、详情文字和规格调整；未完成的 JSON 也能保留。首次升级时从最近一次 `output/task-configs` 任务恢复。恢复配置不会自动执行任务。允许同店铺、同来源商品再次点击“填写并自动上架”，历史提交记录不再拦截新任务。

“参考目标店铺链接”为可选输入：店铺主页会在当前浏览器中打开供核对；带 `itemId` 的淘宝发布表单链接会仅读取已有类目属性，生成 `reference-attributes.json`，不会填写、保存或提交参考表单。手动配置和来源商品参数优先，缺值时由参考属性补齐；目标下拉选项无法匹配时再尝试参考值，仍无法匹配则核对留空。参考属性按当前目标字段名称匹配，SKU和物流参数不复制；实际发布店铺仍核对当前登录账号与配置名称。参考值的替换记录在填写报告的 `reference_fallbacks` 中。

没有手动取值、来源参数及参考值都不可用时，桌面入口会给空白的可编辑文本属性填“无”，并移出焦点后回读确认。已有值不覆盖，原生下拉、只读控件和数字输入框不强填“无”；控件拒绝该文字时保持空白。采用“无”的字段记录在填写报告的 `defaulted_attributes` 中。

1. 输入商品链接、目标店铺名称和完整类目路径（与淘宝页面路径一致，用 `>` 分隔）。
2. 加载 `python_copy/shop.example.json`，按实际情况修改品牌、库存、发货地、运费模板、发货时限和售价规则。保存店铺配置不会混入商品标题或 SKU ID。
3. 类目属性填写 JSON，如 `{"产地":"中国大陆","省份":"广西壮族自治区","城市":"防城港市","包装方式":"食用农产品"}`。这只是来源样本的部分属性示例，不代表适用于其他商品。缺项会在日志中列出。
4. 可指定图片序号、自有详情文字及 SKU 改名/排除/改价规则。默认主图前5张，详情为标题加所选主图；不会自动复制来源全部详情，也不会去除图片中的店名品牌。售价为来源价 × 倍率 + 加价，指定 SKU 价格优先。
5. 点击“仅填写检查”或“填写并自动上架”。后者会在校验通过后直接提交，不再二次确认。日志窗口中按提示登录并回车继续；检查完成前不要关闭窗口。

按店铺使用独立登录目录 `.shop-profiles`。任务配置在 `output/task-configs`，每次运行的结果在 `output/tasks/<店铺>/<来源商品>/runs/<本次运行编号>`。每次新任务拥有独立的 `submission.json`、截图和报告，旧记录原样保留。每次运行只点击提交一次，失败不会在同一任务内自动重复提交；用户再次启动可以重新上架。

类目属性按当前发布页实际字段动态匹配，不使用固定字段清单。先等待详情页参数区加载稳定，再用来源参数补齐手动配置未提供的值。桌面入口延续留空继续的要求：任意必填属性取不到值时记录名称，交由平台校验；设置 `allow_missing_attributes: false` 可要求缺项立即停止。普通文本框直接录入；组合输入框先匹配下拉选项，无匹配时对可编辑控件直接填入并移出焦点，确认值保留后才算成功。只读下拉和原生选择框不强行输入。仍未成功时尝试参考表单值，最后核对留空并记录；若控件残留旧值且无法清空则停止。

桌面入口现在会用详情页参数补齐未配置的类目属性。非空手动配置优先；品牌输入框留空可沿用来源品牌（默认仍为“无品牌”）。只按同名字段填写，不把“包装方式”和“外包装种类”混用，不推测同名但取值冲突的来源参数。来源 SKU 维度、库存和物流参数不会混入类目属性。每次采集后生成 `attribute-plan.json` 标明取值来源，填写成功后的 `draft-verification.json` 记录属性回读、留空的 `skipped_attributes` 及没有对应发布字段的参数。提交前对跳过的字段按空值核对，不再强制要求原始参数值；淘宝自身的必填校验仍可能要求补齐。

通用入口已实现，但当前仅在番薯真实编辑页核对属性发现，未完成新入口跨类目端到端发布测试。遇到不支持的属性、SKU 控件或采集页面会停止，不保证所有淘宝/天猫类目适用。提交后的平台成功提示、商品链接和前台标题会记录；前台规格、价格、物流及详情仍需核对，报告会标明待核验。

以下为原样本入口，仍只填表、不发布；与桌面“填写并自动上架”不同。

独立 Python 实现，不依赖谋臣界插件。实现商品采集、SKU 转换、图片下载和淘宝编辑页填写；没有保存或提交动作。

## 运行

在项目根目录执行：

```powershell
python -m pip install -r python_copy/requirements.txt
python -X utf8 python_copy/copy_product.py --snapshot output/python-copy/745182817868/source-snapshot.json --draft
```

重新采集后填写：

```powershell
python -X utf8 python_copy/copy_product.py "https://item.taobao.com/item.htm?id=745182817868" --draft
```

首次需本人登录或验证，之后复用 `.python-copy-profile`。请核对目标店铺。程序执行后保持浏览器打开，终端按回车才关闭；未保存的编辑内容关闭后可能丢失。

配置在 `target-settings.json`。其中的 SKU ID、图片序号、标题和详情针对本样本，换商品必须调整；不是任意商品通用的一键复制工具。采集适配已观察到的淘宝 SSR 页面，天猫其他布局尚未实测。

## 核对

程序匹配实际 SKU 组合，不生成笛卡尔积。缺失价格、重复组合、未知属性或改名导致规格合并时停止。来源展示库存不作为目标库存。

成功输出 `output/python-copy/745182817868/draft-verification.json` 和 `draft-filled.png`，异常输出 `draft-error.png`。请核对文件时间，旧报告只能证明当时的运行。

外包装、品种、系列等类目属性，以及发货时限、平台服务承诺仍需人工核对。本程序不自动提交，不代表已经发布。

